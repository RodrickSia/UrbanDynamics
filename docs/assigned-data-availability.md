# Data availability for assigned layers

Source availability snapshot checked on 2026-09-30 for the initial Thu Duc scope. The table records source probes from that date; it does not establish current source uptime or data freshness. Flood and land-price ETL code is now present; see [`khoi-implementation.md`](khoi-implementation.md) for the current pipeline and warehouse behavior. Run `node scripts/probe-assigned-sources.mjs` from the repository root to repeat the read-only checks. The recorded live results came from an approved network run.

## Recommendation for a first implementation

1. Intersect the Dataverse GeoPackage with the Thu Duc boundary and validate how many events actually fall inside. Preserve dates, source links and geocoding precision. Because the labels come largely from news reports, missing reports are not evidence of no flooding. One text match alone is far too sparse to justify a calibrated local model.
2. Use Open-Meteo forecast rain and NASA IMERG historical rain as model inputs. A flood prediction requires local flood labels and validation; rainfall alone is not a flood forecast.
3. Render the official price table as a **road-segment reference-price layer**, not a continuous market-price heatmap. Geocoding the published `from` and `to` locations is an additional task. Label the statutory price and year in the UI.
4. Show source, observation time, spatial resolution and uncertainty on each layer. Do not imply street-level depth prediction from coarse weather or satellite grids.

## Probe limitation

The sources had intermittent connection failures during probing. A successful response proves that a file or endpoint was available at the check time, not that it has production uptime. The PDF rows were also checked against the published annex. The script checks PDF and GeoPackage file signatures; it does not extract every land-price row or inspect flood raster pixel values. No street-level flood prediction accuracy, Thu Duc event count, or market-price coverage has been established.
